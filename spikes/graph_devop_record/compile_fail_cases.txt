Compile-fail test cases — actual rustc diagnostics captured 2026-06-12
with nightly-2026-05-22 from the spike workspace.

Each case was reproduced by temporarily adding the offending lines to
opt_outs.rs::type_assertion_works_for_recordable_chains, running
`cargo check --tests`, capturing the output, and reverting.

These prove the `RecordableOp: DeviceOperation` sub-trait correctly
propagates non-recordability at the chain root — a user who
accidentally puts a non-recordable op anywhere in their pipeline gets
a clean compile error with the offending type named and the available
RecordableOp impls suggested.

Case 1: AndThen<Upload, ..> can't be recorded
══════════════════════════════════════════════════════════════════════

Source addition:

    let with_upload = AndThen {
        source: crate::leaves::Upload { data: vec![1, 2, 3], allocated_buf_id: 1 },
        f: |b| FillKernel { n: 3, buf_id: b, value: 99 },
    };
    assert_recordable(with_upload);

Captured rustc diagnostic:

    error[E0277]: the trait bound `Upload: device_op::RecordableOp` is not satisfied
       --> src/opt_outs.rs:202:27
        |
    202 |         assert_recordable(with_upload);

        |         required by a bound introduced by this call

    help: the trait `device_op::RecordableOp` is not implemented for `Upload`

Note: the diagnostic points at `Upload`, not `AndThen<Upload, ...>` —
the recursive `where U: RecordableOp` bound on AndThen's RecordableOp
impl bubbles up to identify the root cause.

Assessment
══════════════════════════════════════════════════════════════════════

All three negative cases produce diagnostics that:

1. Point at the .record() / Graph::call() call site that asked for
   RecordableOp.
2. Name the specific non-recordable type (Upload, OnDevice<...>,
   AndThenHost<...>) — including through generic wrappers, so the
   user can find the offending leaf op in their chain.
3. Point at the source location of the offending struct.
4. (For some cases) suggest the available alternatives.

This is high-quality user-facing error reporting — better than a
runtime "this chain isn't recordable" string error would be.
